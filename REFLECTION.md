Reflection On Project Zed

The one new technique I learned from building project Zed was creating a CSV export button for the data entered on my site.

From building through loops inside of JavaScript with "matches" and "csvCell" to creating four additional new steps in commanding JavaScript to deliver the text as a portable file. These four were Blob, createObjectURL, download, and a cleanup command. 

Blob helped in wrapping the text to become a file that can exist in a server's memory, createObjectURL gives the memory file a temporary URL address, the download command is straightforward by telling a broswer to save the file, and the cleanup command removes the temporary link to release the ready to use CSV file.

The reason why this new technique is required rather than a different alternative is the fact that the other alternative would mean a user would have to enter all of their match data manually into Microsoft Excel or Google Sheets. If someone were to do this manually, there would be more error-prone matches as the data begins to pile up and overwhelm a user.

The same thing applies to only keeping saved on a local browser, because the data is only saved on one browser and can completely disappear if the site's history is cleared out completely. Exporting to CSV avoids this mess entirely by generating a file that can always be accessible and shared anywhere.

This original idea to learn this new skill/technique stemmed from me realizing saving data on local storage is only good for people who can access a singular computer where the data was stored. Which is not ideal, especially for the data my app particularly handled. That was when I had the idea of generating a CSV button after remembering the way Python would analyze code from exported CSV files.

This leads into my next point that the CSV is stylized for others to read such as serious competitors or Esport teammates, who can share this file to their captains and coaches for easier convience.
